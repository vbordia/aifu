## The Question

Consider a 5-4-1 water jug puzzle with three jugs $a$, $b$, $c$ of capacity 5L, 4L, 1L, respectively. A state is represented as a three digit string $ABC$, where $A, B, C$ denote the volume of water present in the jugs $a, b, c$, respectively. For example, 140 denotes a state where jug $a$ has 1 liter of water, jug $b$ has 4 liters of water and jug $c$ is empty.

Two types of moves (state transitions) are allowed:
- `xEy`: pick up jug $x$ and empty it into jug $y$
- `xFy`: pick up jug $x$ and fill up (top up) jug $y$

So the possible moves are: `aEb`, `aEc`, `aFb`, `aFc`, `bEa`, `bEc`, `bFa`, `bFc`, `cEa`, `cEb`, `cFa`, `cFb`.

**Tie-breaker**: in some states, both `xEy` and `xFy` may produce the same output state, in such cases, choose `xEy` to break the tie. For example, from the 140 state, both `aEc` and `aFc` produce the same output state 041, therefore, to break the tie choose `aEc` as the move.

For the 5-4-1 water jug puzzle, the `MoveGen` function takes a state $ABC$ and returns a set of states that can be produced in one move. For example, $\text{MoveGen}(500)$ returns $\{140, 401\}$.

## The Topic in 60 Seconds

Every move costs 1, so the state space is an **unweighted graph** and breadth-first search (FIFO queue) returns a shortest path: the first time the goal is dequeued, its depth is minimal.

Operator semantics used by this puzzle:

| Operator | Valid when | Effect |
|----------|-----------|--------|
| `xEy` (empty x into y) | ALL of x fits into y: $A_x \le cap_y - A_y$ | $y$ gains $A_x$, $x$ becomes 0 |
| `xFy` (fill y up from x) | $A_x > 0$ and $y$ not full | transfer $cap_y - A_y$, $y$ becomes full |

If both operators yield the same state, the tie-breaker says report `xEy`.

## Working — BFS level by level

| Depth | New states | Derivation |
|-------|------------|------------|
| 0 | 500 | start |
| 1 | 140, 401 | `aFb`: b 0→4, a keeps 5−4=1 · `aFc`: c 0→1, a keeps 5−1=4 (`aEb` invalid: 5 L cannot fully empty into the 4 L jug) |
| 2 | 041, 131, 410 | from 140: `aEc` 1≤1 → 041, `bFc` c takes 1, b 4−1=3 → 131 · from 401: `cEb` 1≤4 → b=1, c=0 → 410 |
| 3 | 230, 311 | from 131: `cEa` 1≤5−1=4 → a=2, c=0 → 230 · from 410: `aFc` c takes 1, a 4−1=3 → 311 |
| 4 | **221 = GOAL** | from 230: `bFc` c takes 1, b 3−1=2 |

The goal first appears at depth 4, so the 5-state path is provably shortest.

## Tricks & Tips

<Accordion title="Fast method">
1. Depth = number of moves. The goal first surfaced while processing depth-3 parents, so the 5-state answer is provably shortest — no need to enumerate alternatives.
2. Apply the strict `xEy` rule (ALL of x must fit into y): 5 L can never empty into the 4 L jug, which kills `aEb` from 500 and forces `aFb` as the first move.
3. Never re-enqueue a seen state — 500 kept reappearing via `bFa`, `cEa`, `bEa`; skipping it is what keeps the queue clean and the trace short.
4. Replay the move string as a sanity check: 500 →aFb 140 →bFc 131 →cEa 230 →bFc 221. The third move is the tie-breaker trap: `cEa`, not `cFa`.
</Accordion>

**Answers:** 1.1 `500,140,131,230,221` · 1.2 `aFb,bFc,cEa,bFc`
