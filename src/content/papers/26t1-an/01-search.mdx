## The Question

Consider a water-jug puzzle with three jugs a, b and c of capacities 5L, 3L and 2L, respectively.

A state, encoded as a digit string ABC, denotes volume of water in jugs a, b and c, respectively.
For example, state 122 denotes that jugs a, b and c contain 1L, 2L and 2L of water, respectively.

The allowable moves (actions) are
- `xETy`: pick up jug $x$ and empty it into jug $y$ and jug $y$ is also topped up,
- `xEy`: pick up jug $x$ and empty it into jug $y$ and jug $y$ is still not topped up,
- `xTy`: pick up jug $x$ and top up jug $y$ and jug $x$ is still not emptied out.

For example: $122 \xrightarrow{cEa} 320 \xrightarrow{bETa} 500 \xrightarrow{aTb} 230$.

MoveGen takes a state ABC and returns a set of neighbours that are one move away from ABC.
For example, $\text{MoveGen}(122) = \{ 032, 302, 320, 131 \}$.

## The Topic in 60 Seconds

| Move | Meaning | Amount poured |
|---|---|---|
| $xEy$ | empty $x$ into $y$, $y$ NOT topped up | all of $x$, and $y$ had room left |
| $xETy$ | empty $x$ into $y$, $y$ tops out | $\text{cap}(y) - \text{vol}(y)$ |
| $xTy$ | top up $y$ from $x$, $x$ keeps some | $\text{cap}(y) - \text{vol}(y)$ |

The three collapse to: pour $\min(\text{vol}(x),\ \text{cap}(y)-\text{vol}(y))$; the label records *which side ran out*. BFS explores level by level, so the first arrival at the goal is provably shortest.

## Step 0 — Verify the worked example

$122$: a=1, b=2, c=2.

- $cEa$: c's whole 2L into a (room 4) → a=3, c=0 → **320** ✓
- $bETa$: top a (room 2) exactly from b's 2L → a=5, b=0 → **500** ✓
- $aTb$: top b (needs 1) from a → b=3, a=4... careful: example says 230 — reading it as top-from-full-a: a=5−3=2 → **230** ✓ (that step started from 500).

## 1.1 — BFS from 212 → `212,410,401,131`

Start 212 (a=2, b=1, c=2):

| Level | Expanded | New states (producing transfer) |
|---|---|---|
| 0 | — | **212** |
| 1 | 212 | aE/ET/T-b → **032** · bE/T-a → **302** · cE/T-a → **410** · cE/T-b → **203** |
| 2 | 032 | 230 (c→a), 302 seen |
| 2 | 302 | 502 (c→a), 212, 032 seen |
| 2 | 410 | 230, 500 (b→a), **401** (bEc / bETc / bTc: b's 1L → c) |
| 2 | 203 | 033 (a→b), 500 (c→a), 230 (c→b) |
| 3 | … | from **401** (a=4,b=0,c=1): top b from a → b=3, a=1 → **131** GOAL |

No goal at levels 1–2 ⇒ depth 3 is optimal. Path: **212 → 410 → 401 → 131**.

## 1.2 — Move sequence → `cEa,bEc,aTb`

| Move | From | Arithmetic | Result |
|---|---|---|---|
| `cEa` | 212 | c's 2L empties into a (room 3, not topped) | a=4, c=0 → **410** |
| `bEc` | 410 | b's 1L empties into empty c (not topped) | b=0, c=1 → **401** |
| `aTb` | 401 | top b (needs 3) from a's 4L; a keeps 1 | b=3, a=1 → **131** ✓ |

Note why the last label is `aTb` and not `aEb`: a ends with 1L — *not emptied* — exactly the T-move signature.

## Tricks & Tips

<Accordion title="Exam shortcuts">
1. Classify each pour by WHO limited it: y filled (ET/T family) vs x drained (E family). The label question hinges on the END state of x - aTb here because a keeps 1L.
2. Generate neighbours systematically per pair (a,b), (a,c), (b,c) in both directions - six transfers, three labels each; duplicates collapse automatically.
3. Track SEEN globally; BFS revisits nothing, so levels stay tiny even on the full 6x4x3 lattice.
4. Shortest-path proof = quote the level: '131 first appears when expanding a depth-2 state, hence no 1- or 2-move solution exists.'
5. Sanity-check against the question's own example (MoveGen(122)) - your pour arithmetic must reproduce it exactly before you trust your trace.
</Accordion>

**Answers:** 1.1 `212,410,401,131` · 1.2 `cEa,bEc,aTb`
