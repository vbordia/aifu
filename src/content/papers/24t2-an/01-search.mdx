## The Topic in 60 Seconds

BFS sorts by h, A\* by f = g + h, BnB by g on full paths. A\* is optimal when h never overestimates.

## 1.2 — A* → `S,F,C,A,G`

Path: **S → F → C → A → G**, cost 8+8+4+4 = **24**.

## 1.3 — Branch-and-Bound → `S,F,C,A,G`

Pop the cheapest partial path; ties break by path labels (SE &lt; SF, SFCA &lt; SFCB).

| Pop | Extend | OPEN afterwards (path : g) |
|-----|--------|----------------------------|
| S : 0 | SE : 12, SF : 8 | SF : 8, SE : 12 |
| SF : 8 | SFD : 20, SFC : 16, SFB : 16 | SE : 12, SFC : 16, SFB : 16, SFD : 20 |
| SE : 12 | SED : 20 | SFC : 16, SFB : 16, SED : 20, SFD : 20 |
| SFC : 16 (tie SFB) | SFCA : 20, SFCB : 24 | SFB : 16, SFCA : 20, SED : 20, SFD : 20, SFCB : 24 |
| SFB : 16 | SFBG : 28 | SFCA : 20, SED : 20, SFD : 20, SFCB : 24, SFBG : 28 |
| SED : 20 | SEDA : 28, SEDG : 28 | SFCA : 20, SFD : 20, SFCB : 24, SEDA/SEDG/SFBG : 28 |
| SFCA : 20 | **SFCAG : 24** ← goal on queue | SFD : 20, SFCAG : 24, SFCB : 24, … all 28s |
| SFD : 20 | SFDG : 28 | **SFCAG : 24**, SFCB : 24, … |
| **SFCAG : 24** | goal popped — cheapest open is SFCB : 24 ≥ 24 | → **optimal** |

Path: **S → F → C → A → G**, cost 8+8+4+4 = **24** ✓

## 1.4 — Shortest path → **B, C (both)**

A* and BnB both returned 24; BFS returned 28 → **B and C** (multi-select!).

## 1.5 — Admissibility → **A (admissible)**

Every h ≤ true cheapest cost from that node:

| Node | $h$ | $h^*$ (best real cost to G) | OK? |
|------|-----|------------------------------|-----|
| A | 3 | 4 (A-G) | ✓ |
| D | 4 | 8 (D-G) | ✓ |
| C | 6 | 8 (C-A-G = 4+4) | ✓ |
| B | 7 | 12 (B-G) | ✓ |
| F | 10 | 16 (F-C-A-G) | ✓ |
| E | 9 | 16 (E-D-G) | ✓ |
| S | 10 | 24 (S-F-C-A-G) | ✓ |

No overestimate anywhere → **admissible** ✓ — which is exactly why A* hit the optimum.

## Tricks & Tips

<Accordion title="Exam shortcuts">
1. The h values are printed — build the table before tracing anything.
2. The classic slip in this trace: after expanding F, E's f = 21 is still the minimum — expand E before C. And at the end, D (24) pops before G on the label tie-break. Skipping either still lands the same path here, but the OPEN lists you write lose marks.
3. Watch 1.4: it is multi-select — tick every algorithm whose returned cost equals the BnB optimum (A* and BnB at 24; BFS took 28).
4. Fast admissibility check: compare each h only against its node's cheapest outgoing route to G (A: 3 ≤ 4, E: 9 ≤ 16, ...) — one row per node, no search needed.
</Accordion>
