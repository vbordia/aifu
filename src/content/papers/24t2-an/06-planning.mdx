## The Topic in 60 Seconds

**Applicable** = preconditions ⊆ state. **Relevant** = add-list ∩ goal ≠ ∅ (applicability irrelevant). $A_1$ = applicable in $P_0$ (+no-ops). **Action mutex** (ANY): inconsistent effects / interference / competing needs. **Proposition mutex** (ALL): every producer pair mutex.

> Deep-dive: [Blocks World & STRIPS](/concepts/week-08-planning/01-blocks-world-strips), [GraphPlan Mutexes](/concepts/week-09-goal-trees/02-graphplan-mutexes).

## 6.1 — Applicable → **B, C, D**

armEmpty holds, so only unstacks and pickups are candidates:

| Action | Preconditions | Verdict |
|--------|---------------|---------|
| Putdown(D) | holding(D) ✗ | ✗ |
| **Unstack(D,B)** | armEmpty ✓, clear(D) ✓, on(D,B) ✓ | **✓** |
| **Unstack(C,A)** | armEmpty ✓, clear(C) ✓, on(C,A) ✓ | **✓** |
| **Pickup(E)** | armEmpty ✓, clear(E) ✓, onTable(E) ✓ | **✓** |
| Pickup(A) | clear(A) ✗ (C sits on A) | ✗ |
| Stack(B,A) / Stack(A,C) | holding(·) ✗ | ✗ |

## 6.2 — Relevant → **F, G**

| **Stack(B,A)** | on(B,A), armEmpty | ✓ on(B,A) |

## 6.3 — Mutex action pairs → **A**

$A_1$ = \{ Unstack(D,B), Unstack(C,A), Pickup(E) \} + no-ops of the start facts (options C, D name Stacks — inapplicable here, auto-wrong).

- **Unstack(D,B) ⊕ Pickup(E)**: both delete armEmpty → interference → **mutex** ✓ (option A)
- Unstack(D,B) ⊕ Unstack(C,A): both delete armEmpty → interference → mutex by the standard test too.

The official key records a single pair, **A**. Both listed pairs pass the interference test; if the paper wants exactly one, A is the safe pick — but be aware B is equally mutex under the textbook rule (this is a known quirk of this key). Never tick C or D: those actions don't exist in $A_1$ at all.

## 6.4 — Mutex propositions → **A, B**

$P_1$ = start facts (clean no-ops) ∪ adds: clear(B), clear(A), holding(D), holding(C), holding(E).

| Pair | Producers | Verdict |
|------|-----------|---------|
| **clear(B) ⊕ holding(C)** | clear(B): only Unstack(D,B) (D sits on B); holding(C): only Unstack(C,A); producers mutex (6.3) | **✓** |
| **clear(B) ⊕ clear(A)** | clear(A): only Unstack(C,A) — same mutex pair | **✓** |
| clear(E) ⊕ on(D,B) | both are start facts → their no-ops coexist cleanly | Not mutex |
| clear(E) ⊕ holding(D) | clear(E)'s nop is clean against anything in $A_1$ | Not mutex |

<Callout type="tip" title="The armEmpty hinge">
With armEmpty in the state, every applicable action deletes it — so layer 1's real actions form one mutual mutex clique, every new proposition is locked to its producer's fate, and only start-state facts escape through their clean no-ops.
</Callout>

## Tricks & Tips

<Accordion title="One minute each">
1. Applicable: see armEmpty ⇒ think unstacks/pickups only; then check the two extra preconditions (clear of the top block, on-pair or onTable).
2. Relevant: scan the goal facts and ask which schema adds each one — Stack adds on(·,·), so F and G fall out immediately.
3. Layer-1 action mutex: shared deleted fact (armEmpty) = interference = mutex; options naming non-existent actions are free eliminations.
4. Proposition mutex: write producer sets first. Singleton sets married to mutex producers give mutex (A, B); any start fact in the pair brings a clean no-op along and kills the mutex.
</Accordion>
